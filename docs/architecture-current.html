边界专用版行为
分发包仅 EXE、BAT、说明和许可证。私有构建 profile 将目标网关和访问凭证编译进 EXE；不分发身份私钥或运行时配置 JSON。
每台设备首次生成独立 Ed25519 身份，更新程序时保留。多人共用访问凭证，不共用设备身份。
专用权限网关只发布 sub2api，文件与测速关闭，不启用管理 HTTP / IPC。隐藏配置不是授权措施，最终授权在网关检查。
凭证撤销凭证可提取、可转发。持有者可创建新身份；单独封禁旧 NodeId 不能可靠撤销其接入。批次撤销需轮换凭证并重新分发。
启动与退出BAT 窗口保持运行；Ctrl+C / 关闭窗口停止映射。朋友版没有安装开机启动项；窗口运行期间负责自动重连。
连接预算专用网关构建的 peer 上限 128；普通构建 16。待握手仍为 8；上限不代表完成了 128 台吞吐压测。

主界面、独立窗口与托盘

保留文件传输主界面，接入新的 Agent

主窗口呈现设备连接、本机 ID、接收目录、文件传输列表、队列与任务操作。新的节点管理界面成为二级入口。这里的“原界面”是展示与交互层的保留，业务动作实际发送到 Agent。

设置本机偏好、密码等配置入口
节点管理后台、信令、授权、TCP 服务和规则
连接诊断节点快照与诊断信息
速度测试测速参数与状态
任务详情选中任务的状态与操作
目录预览增量差异与确认发送

六类二级页面各自打开原生窗口。同类窗口重复点击会激活已有窗口；关闭后可重建。它们共享一个 AgentShell 和一个 ClientWorker，不会为每个窗口启动新的节点。输入框的窗口布局与 IME 状态独立。

操作当前行为Agent / 传输
点击主窗口 ×隐藏主窗口及已打开的二级窗口，保留托盘；托盘恢复原窗口。继续运行
点击二级窗口 ×仅关闭该二级窗口，主窗口和其他窗口保留。继续运行
托盘恢复 / 打开重新显示并激活已保留的窗口，共享状态不丢失。继续运行
托盘“退出”向 Agent 发出停止请求，等待数据目录、身份和任务所有权释放后退出前端；失败时保留可见错误。有序停止；不直接强杀
托盘不可用主窗口关闭动作退为最小化到任务栏，避免隐藏后无法恢复。继续运行

桌面是可独立退出的管理进程，Agent 由独立进程承载。当前产品的“托盘退出”会显式停止 Agent；主窗口 × 不会触发停止。--background 是仅启动已有 Agent 的入口，不等同于显示托盘前端。

控制流与数据流分离

IPC 传递“连接某设备、发送这些本机路径、暂停任务”等命令和有界快照。文件字节、TCP 负载、测速数据由 Agent 经 QUIC 传输，不经桌面 IPC 或 Web 网关搬运。

一个连接，多种独立业务流

统一节点连接由一个入站双向流分发器接管，按 File / Service / Speed 路由，避免多个业务竞争 accept_bi()。业务层继续执行各自权限检查。

08

协议、认证与信任边界

边界实现保证与限制
本机管理 → AgentWindows 当前用户私有 ACL 命名管道；Unix socket 权限 0600，校验对端 UID。原生 IPC 不监听 TCP。保护边界是本机用户权限；不用于公开互联网管理。
浏览器 → Web 网关Axum 仅监听 loopback；管理 API 校验 token、Host / Origin 等边界，令牌保存在 admin.token。可选本地入口，随后桥接同一个 IPC；浏览器不运行 P2P 核心。
节点 → 信令注册与查找、签名挑战、候选交换、九位短 ID；支持配置 TLS。短 ID 便于寻址，最终身份以 NodeId / 密钥认证为准。TLS 需配置，不能假设所有信令部署均开启。
节点 → 节点QUIC 加密 + Ed25519 身份与连接绑定校验，统一能力协商与远端密码 / 信任认证。“支持某能力”和“被授权使用”分别检查。认证失败不触发自动降级。
业务 → 本机资源文件方向权限、接收根目录约束、TCP 服务 ID 与允许设备、限额和撤销。授权访问明确的资源，不等于任意远程文件系统或任意网络目标访问。
节点 → Relay经配对认证与限额的 UDP 数据报转发，内层仍是设备间加密 QUIC。Relay 转发密文，仍能观察连接元数据与流量规模；未配置时不提供中继兜底。

本地管理协议

  • api_version = 1；JSON 外层为 4 字节大端长度，帧上限 1 MiB。
  • 请求带 request_id、timeout_ms 和有类型的命令；响应携带结果或错误。
  • 变更请求以 ID + 命令摘要去重；同 ID 不同内容拒绝，结果未知时应以相同 ID 重试。
  • 配置使用 expected_revision 防止多个入口相互覆盖；最近配置提交 ID 持久保存。
  • 事件使用 epoch / sequence，断档需要重新读取快照。桌面当前主要轮询 Status / Tasks，而非持续事件流订阅。

设备间统一协议

  • 唯一 P2PN v2，协商 magic P2PN\x01；服务控制使用版本化、有界帧。
  • 业务流类型为 File / Service / Speed；能力位决定是否支持，资源策略决定是否准入；持续授权通道为必需能力。
  • 文件领域使用 P2PF 专门控制消息、清单和分片数据，不把文件内容塞入节点服务目录消息。
  • 文件完成以持久回执为准；管理命令返回 accepted 仅代表接纳。
  • 业务流队列和帧头处理均有界，繁忙或非法请求显式拒绝。
09

配置、持久状态与数据所有权

通用 Agent 默认数据根：Windows 为 %LOCALAPPDATA%\p2p-file\node，Mac 为 ~/Library/Application Support/p2p-file/node，Linux 通常为 ~/.local/share/p2p-file/node（遵循 XDG）；可用 --data-dir 指定。业务接收根 receive_root 独立配置。专用版使用下表中的独立目录，不读取通用节点的身份或配置。

文件 / 状态内容所有权与恢复规则
identity.key稳定设备私钥；NodeId 由身份派生。Agent 持有身份租约；同身份不能靠更换目录绕开重复运行保护。
node.jsonschema、revision、最近配置请求、信令 / Relay、接收根、信任 / 资源、服务 / 规则、限速等。在线经 Agent 提交；先校验并原子持久化，再发布生效状态。通用配置查询移除密码验证器。
tasks.json + 任务锁文件任务、状态、绑定身份 / 路径、恢复和完成信息。Agent 的任务服务写入，管理入口不直接编辑。恢复依赖检查点和重新认证。
agent.lock + 身份租约目录独占、同身份独占；任务库还有独立锁。启动、退出和离线编辑均要尊重实际持有者。
业务临时文件 / 位图 / 最终文件文件内容、分片确认和发布所需状态，绑定任务接收位置。校验后安全发布；路径约束与目录 capability 防止越界。修改接收根只影响新任务。
admin.token（可选）本机 Web 管理令牌。仅 Web 网关启用时需要，作为私有文件保存。
专用客户端目录%LOCALAPPDATA%\Sub2API-Client：identity.key 和 client.lock。每设备 / 当前 Windows 用户独立生成身份，不保存可编辑的运行时路由配置。锁避免重复实例。
专用网关目录本次 Ubuntu 部署为 ~/.local/share/p2p-sub2api-gateway：identity.key、gateway.json、gateway.lock、runtime.json。gateway.json 保存密码校验值；runtime.json 为代次与恢复状态快照，不是管理 API。升级和恢复不覆盖身份 / 校验值。
发行者构建 profileP2P_SUB2API_PROFILE_FILE 指定私有 JSON：网关、信令、专用访问凭证等。私有构建输入不提交仓库、不放入 ZIP；凭证嵌入 EXE 后可由持有者提取。
内存快照 / 事件 / 预览peer 状态、epoch、事件日志、队列、限时目录预览、界面草稿。均不是持久任务完成证据；Agent 重启后客户端需重新同步。

可在线应用

资源权限、可信设备及来源、服务和转发规则映射、发送并发、自动恢复、接收安全余量、文件限速、接收根目录。密码通过专用命令更新。

接收根先验证可写；既有任务保留原绑定位置。规则监听先准备，配置提交失败不发布新权限。

需要停止并重新启动

信令地址 / TLS、Relay 和业务能力开关等网络运行时配置。使用显式重启配置流程，提交后进入 restart pending 并停止，不承诺透明热切换。

各管理入口共享 revision；冲突时重新读取并处理草稿，不直接覆盖其他入口的更新。

生命周期、并发与自动恢复

外部宿主管理 · 进程退出兜底
Mac launchd / Ubuntu systemd

登录 / 开机启动，异常退出后重启。通用 Mac Agent 的 --managed 检测恢复条件后优雅退出，交由 launchd 拉起。

专用进程内部 · 不替换身份
宿主监测 + Client / GatewayRecovery

采样接口、停顿、核心、通道和服务状态 → 有界决策 → 停止旧核心 → 等待 2 秒 → 新核心重新登记和连接。

↓ 保持身份、配置、授权边界 · 重新收集候选 ↓
共享 Session / QUIC 网络层信令重连保留健康 peer · 已连接 QUIC keepalive · IPv4 STUN 映射 15 秒保活
范围 / 触发恢复动作与保护条件
宿主采样每 5 秒观察一次。停顿 ≥30 秒、接口变化连续确认或核心连续 3 次停止触发恢复。通用 Mac managed 模式退出等待 launchd；专用版在进程内重建核心。
共享 NAT 映射保活每 15 秒向产生 IPv4 公网映射的 STUN 地址发送 Binding Indication，使用原 QUIC UDP socket；无需响应，由 Quinn 独占接收。网络重配置时替换保活任务。
专用客户端通道缺失无设备通道持续 60 秒后重建网络；健康 QUIC 通道不在每次就绪轮询时重复请求信令配对。
专用客户端业务卡住HTTP 未就绪时，每 15 秒探测服务目录，超时 3 秒；连续 3 次失败触发恢复。目录健康而后端 HTTP 异常时等待 Sub2API，不拆除健康通道。
专用网关空闲无人连接且没有待连接时，实际空闲 300 秒刷新候选。存在已连接用户时，不触发空闲 / 失败刷新。
专用网关失败 / 停滞核心至少运行 60 秒；90 秒内 3 次传输失败、待连接阶段 45 秒无进展，或信令 150 秒未确认时重建。密码失败不算传输失败；健康用户优先保留。
长 TCP 流控制配额TcpReady 协商结束立即释放每 peer 的服务控制槽位；HTTP keep-alive、WebSocket、SMB 持续流改由 TCP 总预算持有，不再占满 8 个控制槽导致新请求 RESET_BUSY。
恢复语义：重建后接受新的 TCP 请求；已断开的 TCP 字节流不能透明续接。朋友版窗口关闭后需再次启动 BAT；自动重连不等于开机自启，也不会绕过凭证撤销或持续网络阻断。

场景当前设计
首次运行明确初始化。默认桌面先附着，检测到现有配置才自动尝试拉起 Agent；不会为缺失配置静默创建另一身份。
Agent 启动取得目录 / 身份所有权 → 加载配置、私钥和任务 → 启动会话核心 → 建立 IPC 和规则监听 → 对外提供管理状态。
断线与恢复会话维护代际、候选和 peer 状态。任务恢复受认证、能力、权限、检查点和显式暂停意图约束；不会仅因重连成功就伪造完成。
文件调度FIFO 接纳、发送并发 1–3；传输控制、限速、空间预算和队列有界。文件、测速和 TCP 使用独立业务流，但共享底层网络带宽。
管理请求超时超时不等于操作未执行。客户端保留未确认请求 ID，查询或重试相同请求；配置提交由 revision 和最近提交信息辅助恢复。
配置写入失败避免先发布授权后写盘；有恢复风险时关闭核心并报告恢复要求，保留可审计状态。
有序退出显式 Stop → 停止业务 / 监听 → 等待核心关闭并释放目录、身份与任务锁。桌面托盘退出等待所有权释放。
服务器常驻仓库包含 systemd 用户 / 系统服务模板、macOS LaunchAgent 模板。Windows 当前桌面拉起用户级独立 Agent；并非已经安装为 Windows 系统服务。

状态展示的来源

Agent 提供网络与文件任务快照，桌面工作线程空闲时约每 2 秒轮询 Status / 当前 Tasks 页，界面定时消费更新。所有窗口共享同一投影；Task API 每页最多 128 项。

运行预算

普通构建 peer 上限 16；开启 sub2api-gateway 的专用网关构建上限 128。待连接 8、TCP 总流 256 / 每规则 32，通用 Web 管理并发 32 等预算仍有界。入站三类业务队列各 32，防止控制和流接纳无限增长。

这些数字是当前代码中的控制预算，不代表吞吐基准，也不等于已完成所有规模与网络组合的压测。

功能范围

当前核心围绕设备连接、文件 / 目录传输、增量预览、TCP 服务和转发、测速、诊断、授权与本机管理。Web 是本机管理入口；没有把浏览器变成 P2P 节点。当前不应理解为全网段 VPN、通用远程桌面、任意远程文件浏览器或云账号平台。

开发时应继续守住的边界

新业务进入无 GUI 核心；通用节点由 Agent 统一持有状态，专用模式由隔离宿主持有自己的核心。所有通用管理入口使用同一控制契约。不要在新窗口复制网络运行时、直接编辑在线任务库，或为方便界面展示绕过授权和配置 revision。只维护当前协议；改变线编码需明确版本边界并同步两端。
