## 场景和结果

真实建立 A/B 两个监听和 A 的已接纳 TCP 流；外部 echo/占用 socket 先占 C。新候选 B/C 删除 A、保留 B、新增 C。

| 检查点 | 旧基线实际 SIGHUP | 修复实际 SIGHUP / Windows Web |
| --- | --- | --- |
| C 绑定失败后实际监听 | 仅 B | A/B 均保留 |
| API 有效规则 | 仍 A/B，和运行态不一致 | A/B，与运行一致 |
| last_error | 空 | 有明确错误 |
| A 原流、A/B 新请求 | 旧缺陷不满足完整一致性 | 全部继续成功 |
| 释放 C 并通过同协调器成功重试 | 不作为基线缺陷证据 | 切换 B/C，错误清空；移除 A 监听不截断已接纳 A 流；磁盘配置一致 |

旧缺陷在 Ubuntu WSL 真实 SIGHUP 复现。Windows 明确不支持 SIGHUP，没有用模拟信号代替。旧 Web 自带 rollback，早先尝试用它复现 SIGHUP 缺陷不成立；脚本现禁止 confirm-bug 配合 web，保留失败尝试说明，未算通过。
