# DSH 大消息映射吞吐修复与两端部署验收

核对时间：2026-10-22（Asia/Shanghai）。本次范围为修复 TCP-over-QUIC 映射的大消息吞吐，部署到 Mac / Ubuntu，保留现有配置、映射与 SSH 入口。

## 原因与修复

- 故障发生时 P2P 连接和 SSH 可以保持正常，但 Chrome 的 DSH `/api/remote.mux` WebSocket 约每 15 秒重建。701,883 / 1,013,455 字节会话快照经映射需要数秒；同样的快照在 Ubuntu 回环约 0.1 秒收完。
- 补充只读传输计数后，Ubuntu 发送方向观测到约 15%–16% 丢包、反复出现拥塞事件，Cubic 拥塞窗口降到约 5–11 KB。采样期间 Mac UDP socket 缓冲溢出增量为 0，RTT 约 11 ms，MTU 1452，没有检测到 MTU 黑洞。因此本次修复针对丢包导致发送窗口收缩，不修改系统缓冲、网络接口或 MTU。
- DSH 当前发送心跳间隔为 2 秒，连续两次未响应会终止 WebSocket。大帧及排队数据延迟心跳，与复现的断开相符；没有修改 DSH 的程序、认证或心跳配置。
- QUIC 统一传输配置改用 Quinn 自带的 BBR，按实际交付带宽和 RTT 控制窗口与 pacing，继续使用原丢包检测、重传、身份认证及加密。两端均更新，以覆盖两个发送方向。
- 管理状态的每个已连接设备增加可选 `transport` 计数，包含 RTT、窗口、包 / 字节数、丢包、拥塞、MTU 和流控阻塞。只保存数值，不包含端点、消息内容或凭据；按 generation 匹配更新，兼容旧快照，不改持久配置。

## 回归与对照

- 新增真实 UDP 代理回归：20 ms RTT，握手后每六个下行 UDP 包丢弃一个；经过实际 punch socket adapter 传输 2 MiB，并在同一双向流发送反向心跳。新方案约 0.77 秒完成，数据 BLAKE3 一致，80 字节反向数据完整。
- 临时恢复原 Cubic 做负对照：同一回归在 8 秒仍未收完而失败；随后恢复 BBR，定向传输测试通过。负对照不进入生产构建。
- 26 项 transport、31 项 tunnel、2 项传输统计兼容 / generation 隔离、6 项网络恢复测试通过，共 65 项。
- 格式、架构检查及 GUI feature 的 Clippy（`-D warnings`）通过；构建工具另报告已有依赖的 future-incompatibility 提示，不是本次源码警告。
