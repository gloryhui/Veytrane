- 状态：运行时基础已实现，默认静态检查通过，业务接纳及持久化接入继续在 T19/T20/T25 完成，测试后置。
- 候选：包含本报告的提交；契约：`NODE_WIRE.md`、`NODE_AUTHORIZATION.md`。

每个会话尝试冻结显式 wire 模式和实际装配能力，Unified 使用新协商，旧桌面保留原协商，旧 CLI 未实现时明确拒绝且不降级。新增 unified 构造器，过渡 new 保持旧桌面行为，未擅自升级旧测试/GUI 的线格式。

新增默认拒绝文件/测速的有界 ResourcePolicy、禁用标记和独立 TrustSource。控制快照保留真实密码/信任标记及本地信任来源；管理员预置不产生密码 grant。旧 DesktopConfig schema 未改，来源持久化由 T23/T25 定义。来源记录随信任列表收敛，避免按历史设备无限增长。

显式 disconnect_peer 经同一 actor 失效授权、移除凭据/候选/恢复意图、关闭连接和相关监听，并保留阻止自动重连的有界集合；新显式连接才解除。资源禁用与 Unified 信任撤销同步关闭受影响连接及待认证尝试，旧代发布前复查禁用/断开状态，其他 peer 不被清理。密码轮换沿用原强撤销流程。后续 dispatcher 在新流接纳时读取当前资源策略。

默认 `cargo clippy --locked --all-targets -- -D warnings` 退出码 0（`target/node-t18-clippy.log`）。GUI 同命令附加 `--features gui` 退出码 0（`target/node-t18-gui-clippy.log`），仅既有依赖未来兼容提示。修正一个既有测试配置结构体初始化以保持旧默认模式，仅编译而未运行。

尚未执行 TLS/错凭据/重放、来源、撤销竞争、其他 peer 隔离和进程测试。新模式业务前缀分发接入尚在 T19/T20，不宣称端到端互通或 P3 通过。任务取消/断开完整回归保持待验，数据配置恢复仍由后续规格处理。
