## 变更

Web 和 SIGHUP 复用同一个 AdminState 协调器，包含操作锁、有效快照及 last_error；无 Web 时也创建本地协调器。SIGHUP 获锁后读候选文件，校验/解析/bind/持久化失败记录共同错误，后续成功清空。快照读取也使用同一锁，避免观察半提交。

客户端在 supervisor 锁内 prepare 全部资源，再取得快照/错误写锁，写入文件成功后以无 await 的代码段提交监听与有效配置。取消发生在准备阶段释放候选；取消发生在旧监听任务收尾阶段不会撤销已提交配置。服务端先准备策略写锁，持久化成功后非失败切换；删除了“尝试 apply 旧规则”的回滚流程。

新增 `storage/atomic.rs`：随机 create_new 临时文件、写入和同步、Unix rename/Windows MoveFileExW 替换，不删除旧配置；拒绝目标链接或重解析点。区分替换前错误与替换后的目录同步警告，后者仍发布新有效状态并记录“已提交但持久化确认失败”。本地协调器空 token 不能启动 HTTP。保留 loopback、Host/Origin、请求大小和独立 token 约束。

P1 保留历史入口差异：Web 要有可重启定位 peer 的启用项；本地 SIGHUP 可空规则以撤销全部。手工文件仍是候选，失败不保证启动时自动回到独立有效快照；完整 revision/恢复日志留给 T25，不声称跨资源 ACID。
