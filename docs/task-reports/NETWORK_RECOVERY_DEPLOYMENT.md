## 后续发现：Docker 网桥误触发（2026-10-22）

11:40:46，用户部署发布端口 3003 的 Nginx 容器，Docker 同时创建 `nginx-share_default`（网桥 `br-03e1380e27e7`，网关 `172.23.0.1/16`）。Ubuntu Agent 出现“本机网络接口变化，刷新网络候选”诊断，其 UDP 候选端口变化、连接 generation 增加；两端 PID 和管理 epoch 与验收时一致。Ubuntu 主网卡 `enp37s0` 的地址仍为 `192.168.3.192`，SSH 端口仍为 61132，3003 没有与 SSH 端口冲突。

原因是最初的接口变化策略将全部可用接口集合的变化直接当作强制刷新依据，即使已有 QUIC 连接未关闭也会重建网络，导致既有 SSH / TCP 流中断。自动重连恢复的是后续新连接，不能恢复已断开的原 SSH 终端。排查时 `ssh ubuntu-local` 已重新登录成功，Nginx 容器和 3003 监听也仍存在。

本次补充修复将“接口拓扑变化”与“唤醒 / 刷新失败”分开处理：接口变化先保留仍连接的通道，待关闭或超时后刷新；唤醒和刷新失败的重试仍保持原策略。增加 Docker 网桥增删、真实接口变动后断线恢复、唤醒与接口变化同时出现时的优先级回归。该补充修复在排查时尚未替换上述运行制品；排查期间未重启服务、修改两端配置或操作用户容器。后续经用户授权完成的部署与验收见下一节。
