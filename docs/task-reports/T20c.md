# T20c：监听与已接纳 TCP 流的生命周期分离

- 日期：2026-10-20；实施者：Codex；基线：`2a2fb77`；分支：`codex/node-implementation`。
- 状态：代码与默认静态检查通过，GUI 静态检查及行为验证另记；测试后置。
- 候选：包含本报告的提交；路径范围已补入 NODE_SERVICES 契约。

共享隧道层新增 ForwardStreamOwner，节点级上限 256、单规则 32。停止/删除规则退出监听并释放端口，已接纳 TCP 流留在同一节点级 JoinSet 自然完成；节点退出统一封闭新接纳并 abort/drain，强撤销仍通过原认证连接关闭。旧公共辅助函数保留停止即收尾形态，节点显式使用带 owner 的新形态，不改变旧线格式。

产品错误反馈通道改为容量 32 的非阻塞发送，避免持续失败无限排队。工作任务未轮询就取消时，transport 模式 RAII guard 也会移除自身绑定，不依赖异步 handler 已开始运行；旧代不清理新代 transport。

`cargo fmt --all`、默认/GUI `cargo clippy --locked [--features gui] --all-targets -- -D warnings` 均退出码 0（`target/node-t20-lifetime-clippy.log`、`target/node-t20-lifetime-gui-clippy.log`），GUI 仅已知依赖未来兼容提示。未运行测试，需验证删除时已有字节流持续、端口立即释放、节点退出清理、强撤销、并发上限及未轮询取消。不得据此关闭缺陷或宣布 P3 已验收。
