# 本机导航管理台

入口：<http://127.0.0.1:3001/>。原有导航页内提供映射配置、状态监控和恢复操作，直接打开 HTML 文件时仍可访问服务，但不能使用管理 API。

## 使用

- **新增映射**：选择已有设备与授权服务，填写 Mac 回环监听端口。Ubuntu 支持创建新服务，默认仅授权本机 Mac；Windows 使用其已有授权服务目录。
- **配置**：服务卡片下进入编辑。先检查并预览实际变更，再确认保存。修改已有 Ubuntu 服务的目标时，会提示受影响的授权设备数量。
- **移除**：在编辑区预览并确认，仅移除所选 Mac 转发，不删除远端服务。Ubuntu 管理服务的节点/服务 ID 和目标受到保护。
- **刷新状态**：读取 Agent、监听和 P2P 状态。**核对两端配置**额外通过独立 SSH 读取 Ubuntu 配置。
- **检测链路**：单独检测所选映射。Ubuntu 目标 TCP 通过独立 SSH 检测；HTTP/HTTPS 经映射读取响应，不携带应用凭据、不跟随重定向。401/403 表示需要鉴权，404 表示路径未找到，均不宣称应用健康。仅配置了明确健康检查路径时按 2xx 判断该检查是否通过。私有 HTTPS 目标的证书不作校验，界面明确标注。
- **实时监控**：默认关闭，主动开启后仅在当前页面可见且有焦点时每 10 秒读取运行状态；不会自动探测全部应用、修改配置或重启。切换标签、切换窗口、隐藏页面或离开后关闭，不自动恢复。每次轮询前再次检查可见性与焦点，复选框与实际计时器保持同步。

配置保存成功后服务卡片即时更新，私有导航副本和本机展示设置也随之保存。通过其他管理入口修改后，可在网页重新核对；维护仓库模板仍使用单次命令：

```sh
python3 scripts/update-service-navigation.py --ssh-host ubuntu
```

网页协议、路径、分组和健康检查路径保存在私有 `navigation/control/presentation.json`，单次同步脚本会复用这些字段。未知服务默认仅复制 TCP 地址。登录凭据继续只存在于用户明确启用的私有导航副本中，不写入仓库模板；改变服务目标后不沿用旧目标的登录信息。

## 恢复范围

| 操作 | 影响 |
| --- | --- |
| 启动/停止/重启本条转发 | 仅操作对应规则的监听；保存的启用和自动启动设置不变。既有流的生命周期由 Agent 管理。 |
| 重新连接设备 | 该设备的全部转发可能短暂断开；界面先提示数量，提交后需刷新确认认证成功。 |
| 重启 Mac Agent | 全部 P2P 转发会短暂断开；先提示范围和活动 TCP 流数。优雅停止，确认配置/身份锁释放后，再由现有 launchd 服务启动。锁未释放时拒绝启动第二个所有者。 |

Ubuntu 业务进程、Docker 容器及远端 Agent 的重启未纳入第一版。管理台独立于 Agent，Agent 停止不关闭网页或管理后端。Ubuntu 的管理访问使用独立的 `ssh ubuntu`，并核对它的完整节点 ID 与现有管理映射一致；该 SSH 别名应继续指向独立通道。

## 结构与保存约束

```text
浏览器 :3001
  ├─ 私有 service-navigation.html（内联 CSS / JavaScript）
  └─ /api/navigation/ → 127.0.0.1:17790 独立 Python 管理后端
                           ├─ 本机 p2p-node request - → Agent IPC
                           ├─ 独立 SSH → Ubuntu p2p-node request -
                           └─ launchd → 仅本机已安装的 Agent 生命周期
```

管理后端不持有隧道、不创建新节点身份，也不直接改写 `node.json`。预览限时 10 分钟；保存前重新检查 Mac 和 Ubuntu revision 及端口占用。只改变用户选择的规则或明确预览的 Ubuntu 服务，沿用 Agent 的配置差异应用机制。

两端保存是分步操作：先 Ubuntu，再 Mac。Mac 明确失败时，使用 Ubuntu 当前提交版本尝试恢复原配置；Mac 结果未知时不自动回滚，因为请求可能已成功。失败或结果未知时保留草稿并要求核对状态。管理请求使用操作 ID 和私有持久回执避免重复执行；后端重启后未完成操作仍标为待核对，不承诺跨进程的任意操作恰好执行一次。

后端仅监听回环，管理 API 校验 Host、Origin、浏览器站点来源、专用请求头和内存会话 token；不开放 CORS，不把节点管理 token 放入 URL/网页。请求、并发、预览和回执都有上限。私有状态文件以 0600 原子写入。该管理接口的权限边界是本机当前用户，不能公开反向代理到互联网。

## 安装与更新

```sh
python3 scripts/install-navigation-control.py
# 后续只替换管理后端，等待在途请求结束，不重启 Agent：
python3 scripts/install-navigation-control.py --replace
```

安装器检查既有导航 Nginx 配置，备份后只增加 `/api/navigation/` 代理。运行文件存入 `~/Library/Application Support/p2p-file/navigation/runtime/<内容摘要>/`；独立 LaunchAgent 标签为 `io.github.gloryhui.p2p-navigation-control`，随 Mac 登录启动。它没有定时同步或探测任务。Nginx 配置语法通过后使用平滑 reload。

安装前的导航和 Nginx 配置保存在私有 `navigation/installation-backups/`；操作回执和日志在私有 `navigation/control/`。原有 Agent/Web 服务配置不由该安装器修改。
