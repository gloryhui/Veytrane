# T23：节点配置、提交与恢复

本轮冻结的物理路径为 `node/agent_config.rs`、`node/agent_state.rs`，重用 `storage/atomic.rs`；不修改旧 DesktopConfig schema11 或任务 schema。

## 新配置 schema1

`node.json` 是唯一有效持久根：schema_version=1、revision（初始0）、epoch/last_request（最后提交幂等标识）、完整 NodeSettings。字段含信令/TLS、relay、接收根与文件策略、密码验证器、信任设备与真实来源、显式peer协议模式、文件/测速资源白名单、服务目录、按service ID的本机转发。未知 schema/字段拒绝，不用默认值覆盖损坏文件。私钥单独保存，API配置视图隐藏 verifier 与凭据。新Agent默认UnifiedV1，旧桌面仅逐peer显式启用；LegacyCliV3 不接受。

服务ID唯一，目标仅为服务端配置字段；本机规则必须指定 peer+service ID+loopback监听，不能偷用目标地址作为身份。显式旧桌面规则可保留精确目标地址。最大128服务、128资源设备、128信任设备、256转发规则。新身份只能显式初始化或首启创建，缺失配置/损坏任务都不得静默重新生成身份覆盖现有数据。

## 提交顺序与线性化

单协调锁下检查 expected_revision → 校验全部候选 → 准备全部新增监听/资源（不接纳、不动旧状态）→ 预备运行时提交能力 → 原子写完整新 revision 根 → 无失败提交运行态与内存快照 → 旧监听停止新接入、已接纳流自然收尾。替换前失败保旧；替换后目录sync失败属于新配置已提交并带durability_warning，不能谎报回滚。不能安全准备的端口交换拒绝。所有来源同协调器；SIGHUP只把磁盘候选送协调器，不自己改状态。

根记录是提交记录，不另设一份会互相矛盾的“有效配置”。未命名临时文件不能被恢复当作有效版本。启动先持锁、严格读取根、校验、按根重新准备；任一启用资源无法恢复则启动失败，保留根与错误，不静默删规则。提交后的配置改变在崩溃恢复时仍生效，授权撤销不可因自动回滚旧备份复活。

配置修订不把已建立网络连接伪装为成功重连。涉及身份/信令/协议模式等不可在线安全切换的字段返回 restart_required 且不写盘；用户在显式停止后以离线配置工具提交。新增在线可更改字段必须有全量prepare/commit接口，不能调用旧的先停再bind路径。密码/禁用/信任撤销提交后强制收回旧授权与连接，服务目录及普通规则删除只阻止新流；强撤销路径独立且可观测。

## 预算

现有会话peer上限沿用核心MAX_PEERS；连接尝试/命令/事件均有界。管理32连接，帧1MiB，单请求30秒，缓存1024；分发每业务队列32、首部并发64/5秒；服务每peer8控制流/10秒；本机TCP全节点256、单规则32，接纳失败明确忙。文件发送并发复用原1..8设置和每peer调度，不把测速或慢管理客户端排到文件锁内。公平性验收：双peer各两规则持续流下，另一peer小请求p95不超过单peer基线3倍且不出现30秒饥饿；这是待实测门槛，不是静态检查结果。

## 故障注入表（测试后置）

| 注入点 | 重启/响应预期 |
| --- | --- |
| 校验、bind、临时文件write/sync失败 | revision不变，A/B监听和快照不变，有last_error |
| 临时文件完成、replace前杀进程 | 根仍旧；孤立temp不用于恢复 |
| replace后、内存切换前杀进程 | 新根恢复，不能回退撤销 |
| replace成功、目录sync失败 | 返回新revision与警告，运行新配置 |
| 相同revision双入口竞争 | 一个成功，另一个conflict并带当前revision |
| 同ID重试/不同payload | 相同结果/明确id_conflict |
| 启动新根资源被占用 | 宿主拒绝启动，不部分挂起并声称全成功 |
| 显式回退备份 | 必须预览，撤销权限/新文件不被自动覆盖 |

实现与静态检查分别记录T24–T26，不能用文档替代故障注入。
